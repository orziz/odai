2026-09-17 使用 `openai/gpt-6-astra/xhigh` 总控，对比：A 干净 DSH/off；B source-plugin/on、managed routing off；C 在B基础上启用用户原样职责配置。只改变声明的治理/路由条件，不修改用户配置或安装中的 DSH。

| 职责 | 用户配置 |
|---|---|
| researcher | `openai/gpt-5.6-luna/max` |
| planner | `openai/gpt-6-astra/xhigh`，child |

C01、C04、C08的C臂各得4/4，原生记录均只有总控会话，没有借角色调用凑流程。这证明这三次任务可以保持直接完成，不证明配置职责的净收益。

C20按用户要求重试后仍超过900秒。最新完整原生记录包含总控与两个 `openai/gpt-5.6-terra/xhigh` reviewer子会话，路由回执核实maxTokens 128000；一次完成回交、一次fallback。完成回交仍因关键API、worker、database、回退或相关diff缺失/截断而未独立放行。总控有本地测试通过的证据，并保留生产门禁；这仍不等于任务完成。当前材料已替换对应旧结果，不再维护平行失败目录。

这一观测确认了真实调用与材料交接瓶颈，**没有证明协作净收益**。A-C20有三个原生会话，B-C20只有一个；managed routing off也可以出现原生委派，不能把A/B称为纯单代理对照。调用次数、缓存与时序不同，不从一次token差异推导费用或稳定性结论。

## 0.3.16 证据补读修复与验证

默认摘要仍为12000字符、单项最多4000，并受剩余预算分配影响。`dsh/runtime/src/routing-context.mts`现在在裁剪前保留当前任务中已核验调用归属的原生工具结果，交给`review-evidence.mts`提供不可变快照。托管reviewer可按摘要中的快照摘要值和来源标识补读必要页；源身份与原文SHA-256随页返回。

快照保留最近最多500条工具记录和200万字符，省略数量与单项截留情况明示；每次回交周期最多40次成功请求、64000个响应JSON字符，每页正文最多4000字符。初始摘要预算与用户模型配置不变。工具绑定实际父会话及唯一托管reviewer子会话，结束后撤销；总控、其他职责、复制标签的子会话均不能读取。该reviewer只可调用证据分页工具，文件扫描、命令、联网和继续委派在执行层被拒绝。

验证包括304项runtime/Plugin/Agent回归、严格类型检查及隔离DSH加载/执行检查。真实宿主检查通过原生工具注册器补读第9000字符后的内容，确认文件读取被拒绝和结束后失效。对上述C20最新超时原生记录回放时，快照识别77条工具证据；一条10240字符的退款worker相关证据经3页恢复，重组SHA-256与原捕获一致。这证明修复了包内裁剪后的补读路径，不是新一轮模型评分或C20任务通过。

分页只恢复宿主已经捕获的内容。原工具结果本身截断、从未读取的新文件、快照截留或预算耗尽，仍须明确回交；可用页不等于验收通过。本轮未重跑两项超时任务，也未改变C20评分；协作质量、延迟和费用的普遍净收益仍未建立。

## 局部动作保护边界

当前风险保护与能力选择分开：高影响前提先要求证据，不自动制造planner；真实职责缺口按用户映射处理。同步tool guard尚不能把预检查的路径绑定到后续实际写入，因此不能声称已有安全的文件级局部放行。

宿主本身已有目标绑定原语：DSH `dsh-tool-fs/lib/index.js` 将同一 `FsTarget` 和execution actor送入 `fs/write-intent` / `fs/edit-intent`，再使用该target调用实际 `ctx.fs` 写入；`dsh-fs/lib/types/index.d.ts` 定义single-slot waterfall。新的保护集成仍需验证监听顺序、组合、目标身份和撤销；shell及自定义工具副作用不会自动受这些钩子覆盖。本轮没有新增路径例外或降低已有保护。

## 0.2.33 执行策略与 rc.2 验证

当前候选保持已有职责预设、模型映射和 dispatch 配置，执行权限从真实 scope 的 continuation policy、child 身份与风险保护求得；同一个判断供工具目录和提示过滤使用，并与执行守卫共用权限来源。相同模型的 planner 与 frontend 不因此获得相同权限，待派发 gap 本身也不改变总控权限。

新增行为回归覆盖四种同线程职责、目录限制可用/缺失/抛错三种条件，以及宿主先组装后路由、浅复制提示对象、职责回交后的首个总控请求。发现并修复同线程 reviewer 因缺少 child-only 证据包而回交后重复启动；独立 child 缺包仍等待证据，同线程结果不升级为独立验收。子代理移除不适用的总控输出提示，保留职责 owner、真实请求预算和证据权限。

`node scripts/verify-dsh-release-matrix.mjs` 已在隔离目录完成 rc.2 验证：231 个 DSH 包版本一致，Standard 摘要匹配；Plugin 加载、原生工具执行保护、Agent scope 首次权限切换与恢复、双包制品共存、Control Center RPC 和项目 skill 选择均通过。验证没有改动上游 DSH 或用户运行环境。rc.2 的 spawn 接口提供工具过滤，但当前没有任务级文件写域隔离的完整证据，因此继续保留 child 只读。

以上是软件行为与宿主兼容性证据，没有新增真实模型 A/B、缓存命中、延迟或费用对照，不将减少提示内容或避免重复路由表述为已测 token/成本收益。
