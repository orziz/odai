# 验证与完成

当前结果是否成立仍有具体疑问，或需要判断组合交付、恢复与证据失效时读取。知道怎样完成的小改动不因“需要验证”而先读取本文件。

验证方式按尚未判明的具体属性选择。普通文案、注释、格式或局部样式修改，检查 diff、目标内容及必要的实际效果通常就够；不要为了验证而默认搭环境、启动浏览器、造截图脚本或运行整套测试。涉及行为、共享接口、权限或数据的改动，才按实际影响补相应检查。项目明确要求的检查仍按其适用范围执行。

运行测试前应能说明它要排除哪种具体失败，以及结果会怎样改变交付判断；已有检查或直接观察已覆盖时不追加。新增自动化测试还须覆盖值得长期防回归的行为，且现有测试确有缺口；不为一次性改动、复述实现或固定 Markdown 措辞而新建测试。不把内部判断另写成计划、清单或验证报告，除非用户要求或交接确有需要。

## 建立验收

- 先确认验收对应用户已对齐的真实结果，而非模型自行选择的根因、手段或交付物；再把明确结果、限制、具体对象、输入、位置和不可接受结果映射成可观察证据，证据证明为目标所必需的条件也纳入。
- 只验证相关属性和主要回归风险，每份证据绑定实际覆盖的交付对象与属性。配套构建或测试通过只证明对应配套结果，主要交付物仍须有与用户目标对应的完成证据。测试、构建、静态检查、diff、截图、日志和人工观察不能互相冒充。
- 项目已指定某项事实的权威筛选、查询、命令、样本或来源时，按该入口核验；相似字段、近似范围、替代命令或其他来源不能冒充同一对象与含义。
- 验证强度由失败代价、影响范围、不确定性和已有证据覆盖共同决定；用户可见、工具可用或追求完整本身不构成升级理由。较轻证据已覆盖目标与主要风险时即采用；只有关键属性仍无法判定，或出现失败、冲突与新风险时，才升级到更接近真实场景的验证。
- 验收先写要证明的属性，不把模型自行选择的命令、工具或流程升级成成功条件；只有用户或权威约定明确点名时，指定方法本身才属于契约。指定验证器因当前启动入口或依赖不可用而失败时，先核对现有环境能否用兼容入口运行同一验证器；仍不可用才采用真正覆盖同一属性的其他证据，并明确它没有证明原验证器已通过，不把自写近似检查称为等价。证据仍缺失就如实标明。

## 判断完成

- 用户已对齐的真实结果已经成立，明确要求均有结果，主要风险有相称证据，才算完成。整体整理须核对本体、配套及它们的连接关系，各部分有基于证据的处置结论；保留可以是正确结果，未检查不能写成无需改动。局部未知只阻断依赖它的部分，其余继续交付并保留未完成项。
- 声明、配置和注释只证明“写了什么”；局部观测只证明观测范围；真实调用或使用链才证明端到端结果。
- 审查范围限于点名属性、必要依赖与既有验收。问题须对应已确认要求、必要条件或安全边界；偏好、范围外建议和证据不足分别处理，不能冒充已证实失败。采纳与修正依据原始证据；未发现问题或多份局部通过不能代替完整需求覆盖与整体结果，已证实的失败必须处理。
- 分批改动按最终组合判断结果，复用未受影响的证据；只有组合改变了共享契约、依赖顺序或已有结论的适用条件时，才补查相应属性。修复某个失败项后先重验该项及其受影响依赖，不因又改了文件就重跑全部测试、构建或打包。
- 冲突解决或兼容性编辑须在有效写入授权内，并有对应范围和验收。组合跨越重大安全、数据、并发、兼容、迁移或公共契约边界时，辨明现有证据尚未覆盖的组合属性，再补足相称验证。属性确需独立判断，或用户明确要求独立复核时，须取得能够检验当前依据与盲点的证据；重复自检、复述同一摘要或增加意见数量不能替代独立性。无法取得时只阻断依赖该证据的放行，说明未验证属性和继续条件。
- 改动落地但关键场景未验证时，明确区分已实施、已验证与未验证，不用“应该、看起来、理论上”表达成功。
- 实际结果或用户反馈与原判断不符时，以新证据先纠正当前产物与受影响的完成或放行结论，使相应旧证据失效并修正验收与后续做法；不维护已被推翻的立场。再按教训的适用范围选择局部测试、实现机制或通用规则；推广须有可复现的适用问题与保持项证据，不因一次失误扩大永久流程。
- 版本、候选、阶段、提交、发布或迁移状态属于可验证结果。先核对机器可读事实源、当前产物与真实事件；前一状态未实际结束时更新同一状态，不创建后继值或把当前候选写成历史。确需迁移时，核对权威载体与用户文档指向同一当前值，历史记录按事实保留但不与现役状态争夺所有权。
- 证据足够就停止；每次追加验证前须有尚未闭合、且结果会改变完成判断的具体属性。同一证据范围已通过且没有新失败、冲突、变更或风险时，不重复验证；不能因安心、工具可用、发现范围外问题或追求完整无限提高完成门，也不能因疲劳或流程完成降低验收。

继续旧任务时，先从用户原话、当前产物、主状态、diff 和真实运行结果恢复目标与进度；跳过已有有效证据的完成项，不沿用无证据的旧完成标签。
