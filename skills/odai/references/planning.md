# 工程实施计划

用户明确要求可执行的修复、开发、迁移、重构或专项治理计划，或已授权为跨轮次实施建立持久交接时读取。普通下一步建议、当轮可闭环实现和仅仅“任务复杂”不自动触发计划文档。

本文件只把目标、事实、边界、工作包、验收、停止与续作冻结成可执行合同，不规定已冻结范围内的具体制作工艺，也不选择模型、角色或调度形态。产物如何实现与打磨由 `references/craft.md` 负责；是否取得外部能力或分离责任由 `references/leverage.md` 负责。制作中出现会改变目标、范围、公共契约、用户取舍或验收的分支时，才返回计划决定。

## 适用与授权

- 先区分计划建议、正式计划文档和计划后实施。用户只要求计划时，只调查和交付计划，不修改生产代码、测试行为、schema、依赖、数据或外部系统；宿主 plan mode 有更严格边界时服从宿主。
- 聊天中的计划不自动授权写文件。用户指定产物或项目已有计划惯例时更新该位置；确需持久交接且写入已获授权时，才新建计划文件。
- 计划服务于后续决定和行动，不复述仓库目录或堆满不适用栏目。计划完成只表示路线、边界与验收已达到可执行标准，不表示实现已经完成。
- 需求、非目标、保留行为和不可接受结果由用户决定；能从当前 checkout 查明的事实自行调查，只询问会实质改变合同且无法从现有材料确定的用户决定或外部条件。
- 正式计划记录其依据的用户目标与授权。用户纠正使目标、范围、保留行为、不可接受结果或实施授权变化时，只让受影响的工作包、验收和授权失效；保留仍成立部分，重新对齐后再继续，不用旧计划替用户维持已经改变的目标。

## 事实基线

- 先读适用项目指令，再核对相关工作树状态、目标合同、真实入口、调用方、数据边界、测试和项目权威验证命令。历史报告、旧会话、issue 评论和模型总结只作线索。
- 调查深度只到足以区分当前行为、目标缺口、可行路线和主要风险。窄改动不做全仓盘点；跨 API、持久化、迁移、恢复或外部依赖时才跟踪相应端到端路径。
- 分开目标合同与当前实现。文档或用户决定说明期望，当前源码、配置、测试和真实运行说明现状；冲突同时记录，不让一方冒充另一方。
- 事实使用 `CONFIRMED`、`UNVERIFIED_RISK` 或 `UNKNOWN`。只有当前 checkout 有触发路径和影响证据时才把缺陷或 blocker 写成已确认；未知项附发现动作、决定标准和停止条件。
- 验证命令从 CI、manifest、Makefile、项目文档或已有脚本提取。找不到时写成待发现工作，不凭经验伪造命令。

## 计划缩放

按后续执行真正需要的结构选择最小层级，稳定后不保留更重结构：

- **窄计划**：目标与非目标、当前缺口、必要改动点、必须保持、验证和风险。
- **跨边界或交接计划**：再加需求覆盖、当前与目标流程、带依赖的工作包、允许与禁止范围、失败行为和验收证据。
- **跨轮次、高影响或迁移计划**：再加 checkout 基线、唯一执行状态、阶段门、兼容与回退、故障恢复、真实依赖验收、停止条件和恢复顺序。

Wave 或阶段只表达真实依赖、风险门或可独立验收结果。独立工作包可以并行；共享状态、同一路径写入或前置证据未成立时才串行。无关边界直接省略，不用大量 `N/A` 伪装完整。

## 合同与工作包

只有要求容易遗漏或任务确需交接时，才为独立要求设置稳定标识，并保留用户原文位置、当前取代关系与对应产物；普通修改不先建需求表。工作包只拆实现，不替用户缩小目标。阶段通过、局部纠正、状态询问或“继续”不撤销未冲突要求；无法继续的部分保留为未完成，不能从合同中删除。

需要精确行为合同时使用：

```text
Given: 输入、前置状态和配置
When: 可重复的操作或事件
Then: 可观察成功结果
And not: 明确禁止结果
Failure: 失败状态、持久化与恢复行为
Evidence: 测试、命令、API、UI、数据或外部结果
```

每个工作包只承诺一个可独立判断的结果，并说明：

- 覆盖的合同与可观察结果；
- 相关 symbol、路径或系统边界，以及允许变化和必须保持；
- 前置依赖、失败行为、兼容或回退要求；
- 定向验证、最终证据和会使本包停止或回到上游决定的条件。

已有缺陷具备稳定复现信号且回归价值成立时，计划先定义正确的旧失败和修复后通过条件。无法稳定红测时使用另一种能区分路线的 Oracle 并标明限制；不为了格式强制新增测试，也不把编译失败、fixture 错误或无关失败写成红色证据。

## 验证、状态与续作

- 验收先写要证明的属性，再绑定相称证据。单测、mock、静态检查、E2E、迁移演练和真实依赖各自只证明覆盖部分，不能互相替代。
- 计划就绪至少要求：明确要求均有落点；当前事实与未知分开；工作包依赖和边界可执行；命令有项目来源；主要失败、恢复和回归风险有相称验收；未获授权动作和停止条件清楚。
- 只有任务确实需要中断恢复时才外化执行状态。优先复用已有计划、issue、TODO 或账本；没有合适载体时使用 `assets/task-state.md`，同一任务只保留一个主状态。
- 计划文档承担主状态时不另建独立账本；独立账本承担主状态时，计划只保存账本路径和稳定合同，不复制当前工作包、完成项或下一动作。非主载体不能维护另一份进度。
- 主状态记录用户目标与授权依据、checkout revision 与相关 dirty 基线、当前工作包、已完成项及证据、失效证据、阻断、下一项可验证动作和停止条件。用户目标、相关源码、合同或基线变化会使受影响状态与证据 stale，重新对齐或重验后才能恢复。
- 续作时重新读取项目指令、计划及其指向的主状态；两者相同时只读一次。核对 checkout 与相关 diff，定位首个未完成且已解锁的工作包，从唯一下一动作恢复。聊天摘要和执行者自报不能替代主状态或原始证据。
- 实施状态与计划状态分开。只能根据当前证据标记未开始、实施未验证、已验证、阻断或完成，不使用“基本完成”掩盖未决项。

## 最小交付结构

项目没有既有模板时，按实际需要从下列结构取用：

```markdown
# <任务>实施计划

> 状态：计划就绪；不表示实现完成。

## 目标、非目标与完成证据
## 当前事实、缺口与未知
## 需求覆盖与必须保持
## 工作包、依赖与允许范围
## 验证、失败恢复与停止条件
## 执行状态与续作方式（仅在需要时；非主状态只放主状态指针）
```

交付前删除无用途的章节和占位符，确认计划没有暗中扩大产品范围、写入授权或完成声明，并让下一执行者无需重新决定目标、边界和验收即可开始首个工作包。
