# 工程实施计划

需要正式工程计划或跨轮交接时使用。本文件负责让整体方案达到可执行程度并约束后续实施；具体制作由 `references/craft.md` 负责，完成判断由 `references/verification.md` 负责。普通任务直接想清楚并完成，不为“复杂”自动创建计划文件。

## 先解决整体路线

计划从用户最终结果、当前差距和不可接受结果出发。先核对适用项目指令、真实入口、受影响的调用与数据关系、既有决定及实际基线，再决定结构与实施顺序；窄任务不扩大成全仓调查。用户提供的根因是待核实输入，历史报告和摘要是线索。

解释各部分如何共同实现结果，尤其是跨文件、接口、安装、运行与发布入口之间的连接；不能以每个模块分别能改或各有测试代替组合可行。没有实质路线分歧时不制造多方案。

分清期望、现状、建议和未知。方案需要某种能力不等于项目已具备；未证依赖说明查证方式及缺失时的处理或停止条件，不先写成已有再用实施前确认兜底。材料冲突保留，命令从 CI、manifest 或项目权威入口取得，找不到就标为待查，不凭经验捏造。

## 确定方案，约束实施

计划就绪意味着：用户要求均有落点，整体路线及关键依赖成立，保持项、改动范围、失败处理和完成依据足以指导实施。影响路线的未决项不能假装已解决；它们只阻断依赖部分。只请求计划时交付计划，不修改代码、测试、schema、依赖、数据或外部系统；宿主 plan mode 的更严格边界仍有效。

方案就绪后连同依赖顺序一起固定，按已有实施授权执行。普通细节在这些约束内自主处理，不反复规划、报批或提高验收门槛。冻结不产生新授权，也不覆盖后续用户决定；新证据推翻关键前提时说明事实和影响，不按失效方案硬做。

按能形成可用结果的依赖关系组织工作，不按文件逐个孤立收尾。每个工作包说明它如何补足整体结果、与前后部分怎样衔接、允许改变和必须保持什么，以及怎样确认该部分成立。只有存在真实依赖、风险门、迁移过渡或交接需要时才分阶段；独立部分可并行，共享状态和写域须协调。

要求容易遗漏或需要交接时才建立需求映射，保留原文来源及有效取代关系。精确行为合同按需说明输入、前置状态、操作、成功、禁止结果、失败恢复与证据，不要求固定模板。高影响、兼容或迁移任务补足实际需要的过渡状态、退路和恢复顺序，不堆满无关栏目。

局部修复先确认它能消除目标问题，而非只消除一条失败输出；现有稳定复现可用于防回归，但不为格式造红测或新测试。整体使用结果与主要风险的证据按 verification reference 选择，计划完成不等于实现完成，工作包全部结束也不自动证明组合结果成立。

## 跨轮执行与恢复

只有确需中断恢复时才外化状态；未采纳建议、普通观察和改进候选不自动变成后续任务，能当轮完成的工作不推入队列。聊天中的计划不自动授权写文件；用户指定位置或已有惯例优先，确需持久交接且写入已授权时才创建。同一任务只保留一个主状态，优先复用已有载体；缺少合适载体时使用 `assets/task-state.md`。计划和状态分开存放时互相指向，不复制进度。

持久目标与自动续作只保存待完成结果，不证明计划正确，也不要求用满轮数。每次恢复先核对当前用户要求、实际产物与剩余差距，再决定下一步；不能只找清单中首个未勾项。已经成立的部分不重做，未成立的要求不删除；关联错误反复出现时回到完整结果重判路线，不沿清单继续堆补丁。

主状态只保留能改变继续方式的信息：目标及授权来源、当前方案、相关 checkout 与 dirty 基线、实际已实现和已验证结果、剩余差距、失效证据、关键未知及下一步。续作读取适用项目指令和唯一主状态，核对相关 diff 与真实结果；同一载体不重复读取，摘要和执行者自报不能替代原件。

用户纠正或相关事实变化只使受影响的计划、授权和证据失效，保留仍有效的部分。对外说明已做出的结果和实际阻碍，不用计划百分比或“基本完成”掩盖未完成项。

## 交付计划

按项目已有格式给出足以实施的内容；没有模板时用目标、非目标与现状，整体方案，必要工作及依赖，完成依据和关键未决项即可。只在需要交接时加入状态位置。删除没有用途的章节和占位符，让实施者无需重新决定整体路线即可开始，同时知道什么新事实会使方案需要调整。
