# 外部能力与协作

需要发现、选择、安装、创建或组合外部能力，或需要 agent 协作时读取。

## 总控责任与能力选择

- odai 是唯一用户入口和最终交付 owner。总控持续持有目标、全局状态、实施整合、修正回路与最终交付，不是额外模型或另一层工作流；对结果负责不等于包办全部制作。
- 按真实缺口选择宿主已提供的能力，不按角色名称预拆任务。调查、规划、制作与验收可以分离；单一充分能力能可靠闭环时，在同一线程查明、谋定、行动、验证和交付，不为展示路由启动角色。工作下放遵循下文的授权、隔离与回交要求，总控仍负责整合与验证。
- 下列是现有命名责任的适用范围，不是能力上限或必须启用的目录。其他已暴露的工具、skill 或原生子代理可以承接有界工作，不冒充已配置角色的模型身份、权限或独立性，也不因专业名称就新增持久角色。
- **researcher** 只补多源事实获取与原始上下文压缩缺口。只有一个会改变后续决定的具体问题需要多份权威来源或较大材料，且有界来源账本能直接补足该决定缺口时才使用。它只读返回事实、精确来源、权威与时效、冲突、未知和停止依据，不选方案、冻结计划、实施或放行。单一权威来源、普通仓库查看、实现期调试、泛泛“调查”、任务复杂或仅有便宜模型都不触发；总控或 planner 仍抽查每个会改路的原始来源。
- researcher 运行时只判任务适配，不感知模型价格；映射只是用户显式启用窄触发，不证明或保证降本，缺可比权威价格与实测 usage 时不得作节省承诺。
- **planner** 只补独立判断缺口。当用户前提、根因、路线或验收设计仍有会改变结果的分支，且新上下文能增加当前线程拿不到的判断时才调用。planner 只冻结目标、证据、边界、决定、验收与停止条件，不预做实施；完成后把有界计划交回总控。原任务已授权实施且目标与范围未变化时，总控接回计划后继续实施，不再等待用户说“继续”；plan-only、新任务、扩围、授权变化或缺少用户决定时先重新对齐，用户纠正的影响遵循 `SKILL.md`。
- **reviewer** 只在独立判断能改变尚未放行的具体属性时使用。用户明确要求独立复核时，独立性本身就是验收属性。
  宿主把当前有效的用户决定及其精确相关原文、对齐问题与用户回答、规划、实际 diff 与决定性工具结果各保留一份组成不可变证据包；后续明确决定只取代与其冲突的早期要求，未冲突要求继续有效，assistant 摘要不产生或取代用户决定。reviewer 不扫描仓库或重复成功检查。实施偏差回总控，路线失效回总控或 planner，缺用户决定或外部条件则停在安全边界。
- **frontend** 只补界面设计或前端制作的专业能力缺口，不是领域资料包；其他专业缺口按实际可用能力处理，不复制这一名称或映射。只有当前总控不能可靠闭合且专长能改变成品质量时才使用；局部样式、文案和窄修复直接完成。宿主可在当前线程取得该责任，也可启动有界独立上下文；责任合同不绑定模型、预算或调度形态。目标、范围或验收未冻结时回 planner 或总控，冻结后的具体制作与界面验证遵循 `references/craft.md`，不在本文件复制工艺。
- agent 启动默认选择新鲜独立上下文，只交付按缺口裁剪的有界任务包，不得复制完整总控会话。任务包只保留当前有效决定及其必要精确原文、被取代决定的最小关系、当前目标与约束、责任合同、commit / diff / 文件指针、决定性工具结果和未决问题，省略完整会话、长聊天、重复工具输出与过程叙述。
- 任务包显式写明用户当前主要语言；除正式产物另有用户或项目约定外，任务标题、委派说明与回交都使用该语言，避免宿主原样转发异语内容。
- 只有无法可靠裁剪的既往交互本身就是决定性证据、宿主可核实继承范围，且有依据判断其收益覆盖输入、缓存失效、上下文压缩和延迟代价时，才继承既有会话。继承范围未知时不使用 fork；实际用量未知时不宣称节省成本。
- 高后果只提高证据、授权和验收强度，不自动制造角色调用。调用前说清具体缺口、将改变的决定或新增的独立证据，再依据任务与已知能力判断预期收益是否覆盖启动、交接、重复读取、复验和延迟。预期不是已证收益，也不要求首次调用先有该调用的历史结果；说不出贡献就不调用。
- 调用后核对原缺口是否闭合、结果是否可用，以及实际增加的交接和复验负担。结果无效时不因已经调用而继续依赖；质量与成本改善只有可比证据成立后才宣称。稳定采用某种分工须有重复任务中的实际依据，不从一次顺利回交推广为默认流程。

## 宿主能力与降级

- 能力目录只认宿主已提供的系统说明、工具定义、已加载配置和实际调用结果。从中确认当前能力、可选责任、选择方式与继承语义；宿主已暴露的事实不再请用户重复，未暴露的能力不猜。
- 当前模型不能自切换，但能通过独立 subagent 或宿主角色取得所需能力时，仍按可获得能力处理。能力可比时用最低充分的已核实责任；不可比时按与当前缺口相关的已证能力选一个足够的责任，不强行排全序。
- 原生子代理与职责路由是取得能力的可选路径，不是前后两层流程。同一缺口只选一条足够的路径；宿主原生工具已满足上下文、权限、模型选择和回交要求时直接使用。角色合同用于约束职责，适配器只补缺失能力、用户映射或可核对的证据；不为取得角色标签重复启动、扫描或裁判，既有回交可按其实际覆盖复用，但不追认未取得的独立性、模型身份或授权。
- 路由是否成立看实际调用，不看配置或自报。分别核对责任是否执行、所需独立性是否成立及指定能力是否实际取得；同一模型的独立上下文可以提供独立复核，不能冒充模型升级。按宿主可见证据核对身份、配置与用量，未暴露项标为未知；用量缺失限制成本结论，不抹掉已核实的交付证据。
- 调用失败、责任身份不符或所需独立性无法核实时，不把回交当作该责任的有效证据。只有新的可核查修正依据才支持重试，并服从宿主的重试上限与停止条件；没有新依据或反复同因失败就安全降级。
- 不能取得所需能力时，继续当前能力可安全推进的部分；只阻断依赖该能力的不可逆放行，并准确说明未取得独立调查、规划、前端制作或验收的实际影响。不把宿主限制说成任务失败，也不伪造路由成功。
- 调用后优先等待一次宿主完成事件或最长有界等待，不反复轮询、播报不变状态或重发累计上下文。

## 安装宿主路由

- 只在用户明确要求为当前宿主安装、更新、卸载或修复 odai 路由时进入这一节。从宿主已暴露的真实目录与调用结果选择 controller、planner、reviewer 以及可选 researcher、frontend，不凭名称猜能力顺序，也不要求用户手填可发现的 ID。
- 只安装 `auto`：单一充分总控直接闭环，其他责任仍只按真实缺口调用。researcher 与 frontend 映射默认不配置；只有用户明确选择各自模型且宿主支持时才生成，二者都不从 controller 或其他责任继承。宿主路由不注入每轮前置流程，也不预设能降低延迟、token 或成本。
- 说明作用域、持久化影响、各责任的实际映射与新会话生效条件，得到一次授权后，使用 `scripts/install-routing.mjs`。默认只处理当前项目，用户明确要求跨项目时才处理 user 作用域。重复安装原位更新自身托管文件，并安全移除旧版 advisor、implementer、worker、executor、stage runner 与跨 provider runner；卸载只删除清单内且未被外部修改的文件。发现冲突或外部漂移就停，不覆盖。
- 安装后开启新会话做一次有界调用。Codex 用随包核验器对账真实角色、模型与推理档；Claude Code 由托管设置选择总控；Copilot 没有可移植的项目默认总控设置，使用安装结果返回的显式模型与 agent 启动命令。
- 未安装路由器时，odai 仍完整可用，按普通单模型路径完成任务。宿主路由不是 skill 的必选依赖。

## 使用、安装与创建其他能力

- 先判断当前内置能力是否真有缺口。做法尚未想清楚不等于能力不足：能由当前模型结合上下文推理、必要资料或授权内的判别性验证解决时，主动推进；已有证据表明需要专长、独立性或访问能力时及时借力，不为证明自主而反复硬试。外部能力只有在正确性、兼容性、可验证性、真实交付或重复成本上的改善，明显大于安装与学习成本、权限与数据暴露、安全风险、上下文占用、维护负担和锁定效应时才值得引入。
- 项目或宿主已有明确匹配的 skill、工具或插件，且它能改变结果时直接使用。skill 须完整读取对应 `SKILL.md`，其他能力遵循权威接口和项目约定。纯本地、已授权且不新增副作用的使用无需另问；安装、启用、联网、外部写入、凭据或更高权限仍按动作边界处理。
- 没有匹配能力时，内置能力足够可靠就继续完成。只有缺口会实质影响结果，且现成能力值得引入时，才查用户允许的真实目录与权威来源。核对候选的原始说明、来源、适配面、维护状态、权限与验证方式，优先推荐覆盖缺口最窄且可信的一项；无法核实时只描述所需能力，不编造具体名称。
- 推荐时说明名称与来源、为何匹配、会获得什么权限、安装后如何验证，以及不用它的替代路径和差异。安装或启用须有用户授权；既有授权已覆盖本次对象、范围和副作用时不重复询问。获准后的第一步必须可执行，不把尚未满足条件的后续步骤写成已可开始。
- 用户明确要求固化项目专属流程，或实际重复使用已显示稳定收益时，可评估项目级 skill。依据真实实例和适用边界形成可发现、可重用、可验证、不固化当期数据的契约，不设机械的实例数量门槛；只有预期而未验证的收益须标明。创建仍须由当前用户请求或项目约定授权；已有 owner 原位更新，不建平行 skill。
- `.odai/local.md` 只是项目叠加层：补项目事实、常量、禁区、术语和已有验收入口，不允许覆盖 odai 总纲、核心门、宿主指令或当前用户决定。重复的项目工艺不得无限堆进叠加层；达到上述条件后再提炼为 skill。

## 组合与下放

- 单一能力已能完整解决就不组合。需要组合时，先说清每项能力独立贡献的结果、交接契约和唯一状态 owner；重复覆盖或可互换的能力只选一个。外部 skill 先遵循其自身工作流，再由 odai 统一边界、证据、验收与交付。
- agent 只用于边界明确、结果可复核，且独立上下文、真实并行、已授权的环境或访问差异、非脚本批量复用或高代价结论质疑中至少一项能改变结果，并且收益高于启动、交接和复验成本时才使用。上下文高度相关、写入冲突或结果不可复核时不下放。
- 制作可以下放为只读产出：给出当前基线、目标文件、必要原件、允许变化、保持项和验收，让子代理返回具体方案或待应用补丁。补丁是建议产物，不是已经落盘、执行或通过验证的结果；总控核对基线、范围与语义，应用后验证组合状态。研究、规划和审查责任不因工具只读就自动变成补丁制作责任。
- 只有宿主实际支持、任务授权覆盖且写入范围与隔离可核对时，才下放直接写入；不能以角色名称、提示词或工作目录自报替代权限保护。写入下放前明确目标、允许写域、禁止范围、验收、停止条件和必读来源。下游无法访问对应原规则、项目来源或确认同版时，不做写入，退回只读产出。摘要不能替代原规则。
- 多个写入者使用同一 baseline、精确允许路径和独立验收。路径重叠、依赖紧密，或不能隔离写入与验证时改为串行；真正独立时才用 worktree 或等价隔离并行。
- review 只读，根据代码、测试、diff 和原始需求给 finding；不修代码，不为了绿改验收条件。finding 冻结稳定 ID，修复责任只接该清单并逐项回交状态与证据；未出现的建议不自动进入写域。
