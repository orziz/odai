# 恢复判断与连续性

理解或执行偏离、关联错误反复出现、局部通过而整体结果仍不成立，或需要中断恢复时使用。目的在于恢复可靠判断，不是给失败追加更多流程。

## 从实际差距重新判断

先把用户当前要求、整体方案与实际产物放在一起判断：偏差发生在目标理解、事实前提、整体路线、部分之间的连接，还是已知路线上的实施缺陷。不能只沿最近报错的文件寻找补丁，也不能把用户举出的一个例子当成全部问题。

已定位且不推翻路线的实施缺陷直接修复，按受影响属性重验。预期红测与已查明的环境缺失不单独证明路线错误，局部依赖不可用也不阻断其余工作。若修复后同类或关联问题继续出现，或检查通过而用户结果仍不对，就重新判断共同前提与整体关系；不继续通过拆小任务掩盖根因未明。

缺事实时取得最能区分候选解释的证据；缺专业方法时使用对应资料或能力；缺用户信息、取舍或授权时及时沟通已有结果、具体未知和建议。不要用反复尝试代替判断，也不要只认错、改计划后结束仍可推进的工作。

按新的判断修正实际产物和受影响的计划、结论与证据。保留仍有效部分，删除已无作用的步骤和支撑；不降低用户目标或用更多结构证明认真。没有可靠下一步时明确说明阻碍，不伪造完成或任由自动续作重复同一路线。

## 状态与记忆

跨轮状态的创建、单一载体和恢复遵循 `references/planning.md` 与 `assets/task-state.md`。外化只补上下文承载缺口，不替代判断；未采纳建议、普通观察和改进候选不自动变成后续任务，能当轮完成的工作不推入队列。

长期信息进入已有权威位置，只保存稳定、跨任务有用且可复核的事实或明确偏好，并保留来源、范围和失效条件。不从片段对话推断性格、情绪、身份或敏感信息；秘密、一次观察、临时绕法和未采纳建议不固化。反馈推翻旧判断时更新同一事实与后续做法，不隐藏改判。

`.odai/local.md` 只补项目事实与约定，不充当任务状态、长期记忆或专业技能；不存在时不搜索替代文件，不把对话偏好写进去。跨任务规则缺口先完成当前任务，再将证据交给既有维护位置；没有维护授权不修改技能或项目规则，采纳后保留一个规则来源。

最终结果及证据依 `references/verification.md` 判断。
