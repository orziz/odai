# Odai 编排

本技能以 `odai` 的治理为前提，负责何时分工、如何交接和怎样收回结果。先取得当前已加载的治理；没有提供时读取同级 `odai/SKILL.md` 或宿主实际安装的 `odai`，不要维护治理副本或用本技能替代授权。

## 使用

- 启用编排不等于每个任务都派角色。当前能力足够时直接完成；只有独立判断、专业能力、访问差异或真正并行能改善结果时才分工。
- 选择职责和准备交接时读取 `references/orchestration.md`。controller 持有整体结果，researcher、planner、reviewer、frontend 是可选职责预设，不是固定阶段、模型等级或权限来源。
- 宿主已有符合要求的原生能力时使用它；配套适配器只补模型映射、生成、安装和调用核验。按当前用户映射与真实工具权限执行。
- 治理、编排与宿主权限分别有效。DSH 已内置本技能时使用其现有能力；不额外运行其他宿主安装器。

## 安装与配置

安装本技能和 `odai` 使规则与脚本可发现，不自动修改宿主配置。用户要求配置路由时：

1. 从宿主确认实际模型、能力与作用域。controller、planner、reviewer 显式映射，researcher 和 frontend 按需选择；不填造模型 ID。
2. 先用 `scripts/build-routing.mjs --help` 查看生成接口；治理安装位置不相邻时显式传入 `--governance-root`。
3. 需要持久安装、更新或卸载时使用 `scripts/install-routing.mjs --help` 对应入口，说明映射、写入范围与新会话生效条件。已有授权覆盖本次动作时直接执行；否则完成准备后取得授权。
4. 按安装结果在新会话核对真实角色和模型。生成成功只证明文件生成，不证明路由已调用。卸载与更新使用托管清单，遇到外部修改不覆盖。

没有宿主适配或无法取得所需能力时，继续安全可完成的部分，准确交付剩余缺口。不要把技能已安装、角色已配置或一次自报当成调用和收益证明。
