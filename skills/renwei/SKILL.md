# Renwei

“人味”：把一眼能看出批量生成的内容，改成有主人、有受众、有分寸的作品。它负责表现工艺，不替用户决定目标、受众和品牌取舍。

AI 味大多在生成那一刻就定了：套路构图、细节过碎、过分工整、结构错误和风格割裂很难靠后期救回，通常要改约束重新生成；事后能稳定清掉的主要是噪点、套话、局部假字和元数据。所以生成前先用，生成后再查。

## 原则

- 具体胜过华丽：用真实的名词、动作、数字和画面，删掉撑不起事实的形容和口号。
- 一致胜过精致：一组素材、一套文案要像同一只手做的。宁可朴素统一，也不要单件惊艳、整体拼贴。
- 真实胜过摆拍：宣传优先用产品本身（实机、真实截图、原有音乐与美术）来组合，不另造模板化场面。
- 少而好：同质内容越多越稀释，能删就删，能合并就合并。
- 去味不去质：去掉批量痕迹，留住笔触、质感、明暗层次和语气；不矫枉过正成平涂或白开水。
- 不属于你的原文不动：合作方提供的、授权的、法务的、引用的文本和素材逐字保留，润色范围之外不碰。
- 不歪曲：润色不改事实、数值、承诺与范围；本地化译意，不加戏。

## 生成前：把味挡在外面

1. 确认受众、用途、载体、尺寸或字数限制、交付格式，以及保存、上传、发布是否在授权内。
2. 找真样本：产品自己的画面、已认可的文案、真实截图与录像、品牌和项目规范。新内容向真样本对齐，不向生成器的默认风格对齐。
3. 把约束写进提示词或提纲：具体对象和用途、要对齐的样本特征、明确的禁止项；一次只做一个主体或一件事。具体写法按需读取：图像看 `references/visual.md`（生成前），文案看 `references/copy.md`（动笔前）。
4. 借其他模型或工具干活时同样给出明确约束，并逐条审查回交结果；新添的口号、套话、额外含义和风格漂移一律退回。

## 生成后：查清、分层处理、在最终形态验收

1. 从实际交付物出发：上线的文案、商店页、包体里的图、成片和缩略图，不只看源稿或提示词。先盘点哪些东西真的会被人看到。
2. 逐项指出具体症状和出现位置，按“影响大、改动小”排序，不用“整体感觉”代替证据。先查结构和事实，再查与真样本、同组内容是否一致，最后查表层；具体排查与工艺按需读取：文案、口播、界面文字与本地化看 `references/copy.md`，图像、视频、噪点与元数据看 `references/visual.md`。
3. 分层处理：整图的结构错乱、构图套路或风格割裂，优先把问题具体写进提示词重新生成（没有重生成条件时替换素材）；已有文案的事实错误直接修正，局部假字可清理后用真实字体替换；噪点、套话和元数据再做清理。图像的测量、去噪、改前改后对比图和元数据检查（PNG / JPEG / WebP）用 `scripts/clean-image.mjs`（只需 Node，不用模型；交付前看对比图）。
4. 同一类问题第二次出现，就把对应约束补进提示词模板；需要写进项目规范时先征得用户同意。
5. 在最终形态里验收：实际页面、实际尺寸、实际包体或成片。交付时说明改了什么、依据哪些真样本、怎么验收的，以及哪些没法验证。

## 边界

- 不作无法核验的宣称（如“零 AI”“纯人工原创”或“内嵌水印已清除”）；平台或法规要求保留的披露与必需版权信息不擅自删除。
- 文件层来源元数据（C2PA / Content Credentials、EXIF、XMP、IPTC、PNG 文本块等）只在交付副本上清理，原件和来源记录保留。像素或信号里的内嵌水印（如 SynthID）不在本技能处理范围内，转码、截图、缩放、裁切和去噪都不能证明已去除；需要无水印素材时从上游换用无水印来源。
- 项目指定了生图或修图模型时照办；神经网络超分、局部重绘也算用模型改图，未经允许不换用其他图像模型。
- 对外发布、上传、替换线上内容仍以用户授权为准；本地文件改好不等于线上已更新。

若由 odai 调用，返回改动、依据、验收证据与未决项，由 odai 统一核对目标、边界与最终交付。
