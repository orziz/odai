# 图像与视频去 AI 味

## 生成前：定样本、写约束

- 用产品里已认可的资产做标尺：比例、线条、调色板、光照、像素密度、字体；项目有画风规范或固定提示词前缀就照用。
- 角色与物件先备参考拼图，比如按顺序排好的角色表、旧版本、已定稿造型，用它们定造型和尺寸。参考图只学它被认可的部分（比如画法），不连带学它的构图和错误。
- 提示词写具体：对象和用途（立绘、头像、图标、背景）、构图与机位、主光源、主色、画法（线条粗细、明暗分几层）。不写“精美”“细节丰富”“大师级”这类空词，它们常把画面堆满没有主次的碎细节。
- 定主次、破均质：焦点画细，边缘和背景敢松敢简；陈设聚散错落、有满有空，不要等距成排、对称阵列或全图同密度精修；需要生活感时留轻微不对称、笔触轻重和使用痕迹，不做样板间式无瑕打光。
- 写明禁止项：任何文字和似字非字、该题材反复出现的套路母题和对称陈设（如成排灯笼、酒坛、牌匾）、满屏发光和漂浮光点、没有主次的碎纹样。需要文字的地方留空，事后用真实字体加。
- 涉及易出错的结构时提前写死约束：如五根手指、肢体与透视比例、器物被遮挡后的两端共线；特殊角色按设定写清（如兽耳角色不画人耳、鬓边用头发盖住）。
- 一组图每张换机位、主光源和主色；一次只做一个主体更容易统一，群像按参考表指定站位。
- 像素画写明目标尺寸、统一网格、有限颜色、不要抗锯齿和渐变，五官和身体用同一网格，免得事后取样改脸。
- 要透明底而生成器的透明通道不可靠时，改要纯色背景（如品红），事后从边缘连通抠图。

## 生成后：先盘点，再按顺序查

- 列出用户会看到的全部视觉内容：产品内（界面、图标、角色、背景、插画），宣传与商店（头图、胶囊图、海报、封面、截图），视频（预告片、动图、缩略图）。
- 检查对象是最终交付物：构建产物、包体内资源（含内联、图集和打包加密的资源）、导出文件、已上传的线上副本。源文件改好不代表旧导出或线上已更新。
- 按实际显示尺寸排先后：被放大铺满屏幕的封面和背景最暴露噪点；缩小显示的头像会把小斑块平均掉，但线条和颜色问题仍在。
- 查的顺序：结构 → 与参考和同组素材的一致性 → 构图与密度 → 假字假标 → 噪点与透明边 → 元数据（具体症状见下节）。
- 整图的结构、一致性和构图问题优先回到提示词重新生成，把看到的问题具体写进约束，不靠后期硬修（没有重生成条件时直接替换素材）；画面本身过关、只有局部假字假标时，可直接修掉或用真实字体覆盖。噪点、透明边、近似色和元数据再走后处理。别拿“不完美”放过结构错误、假字和脏噪点，也别为了“做旧”乱叠廉价脏滤镜。
- 同一问题第二次出现，就把对应约束补进提示词模板；要写进项目的生图规范时先征得用户同意。

## 常见症状

- 模板构图：同一组图反复出现相同母题和机位，比如月亮、瀑布、远山小塔、成排灯笼、正中英雄位、逆光剪影。
- 细节过碎：满画面细碎细节，没有主次，质感糊，光源乱。
- 噪点：平涂区和暗部散落着和四周都不同色的杂点，一块颜色里夹着许多相差无几的色阶；渐变有色带或斑驳；轮廓外一圈半透明脏边，或本该不透明的地方透明度不到满值（透明底的生成图常在 250 上下）。生成插画的平涂、头发和皮肤里常有细密的鳞状纹理和几像素大的斑块，缩小看不出，要放大看。生成视频里纹理游动、闪烁。
- 假字假标：招牌、书页、符纸、横幅、徽章上的似字非字；虚构的标志与印章。
- 结构错误：手指和肢体错乱，器物互相穿插，透视与比例不对；兽耳角色又画了人耳；刀鞘、杖杆被手或衣袖挡住后两端不共线，或下半截消失。
- 风格割裂：精修插画配简单图元；不同角色同一张脸；主角色满身花纹而配角干净；各批次色调不一；同一角色在立绘、头像、小人和动画帧里脸型、领型、主色或手持物对不上。
- 假像素、假手绘：看着像像素画，却没有统一网格，带抗锯齿和渐变，非整数缩放发糊。
- 过度渲染：高饱和，到处发光，HDR 感，塑料质感。

## 后处理到媒介

- 像素画：按检测到的真实像素网格重采样，压到有限调色板，再整数倍最近邻放大；裁掉透明边；确认落脚点和影子对齐，非对称造型按支撑点而不是图片中心定锚点。同一角色的各帧共用一套颜色，免得动画闪色。
- 插画与界面：统一描边、色板和阴影方向，去掉多余纹理和光效。文字一律用真实字体后加，不让生成器画字。
- 抠纯色背景：只从画布边缘连通的区域往里清，不按颜色删内部像素（头发、袖子可能和背景同色）；留下的像素保持原有透明度，不靠把边缘渐隐来消脏边。
- 尺寸：按平台规格出图，宁可裁切也不拉伸放大；像素素材只用整数倍。

## 去噪点

工具是本技能的 `scripts/clean-image.mjs`，由代理调用：只用 Node 自带模块，不用模型；`measure` / `cel` / `pixel` / `review` 处理 PNG，`meta` 支持 PNG、JPEG、WebP；输出不会覆盖输入。在项目里运行时写出它的完整路径；每个命令加 `--json` 输出一段结构化结果，便于写进交付说明。项目脚本也可以直接导入 `cleanCel`、`cleanPixels`、`measureImage`、`reviewSheet`、`inspectMetadata`、`stripImageMetadata`。

- 流程：`measure` 先量 → 按素材类型选 `cel` 或 `pixel`，输出写到新位置并加 `--review <临时目录|对比图.png>` → 用看图能力逐张看对比图 → 有问题换档、换模式或指定区域重看，修不好的退回并写明原因。只凭数字不算验收。
- 对比图：`--review` 或 `node scripts/clean-image.mjs review -o 对比图.png 改前.png 改后.png` 上排是改前、改后全图（黄框标出放大的区域），下面每行左改前、右改后，最近邻放大改动最大的几处（透明区叠棋盘格，便于检查脏边与透明通道改动）；`--region x,y,宽,高` 再指定要看的地方（坐标按改前图）。像素图的改动遍布全图，自动选区不一定落在脸上：先看全图找到脸，再指定区域。看脸、眼睛、高光、细线、文字、唇色，以及雨丝、木纹、笔触这类有意的细纹理。像素图用 `pixel --review`，它按真实网格对齐；单独的 `review` 遇到尺寸不同的两张图只能按比例对齐。
- 先量再改：`node scripts/clean-image.mjs measure 原图.png [改后.png]` 给出颜色数、看不出差别的近似色、孤立像素和半透明像素占比、平坦区细纹、像素网格与元数据块；给同尺寸两张图时再给色调偏移、线条锐度和改动像素比例（尺寸不同时只输出各自统计，不报错）。和真样本或改前对比，明显偏高就是噪点；透明通道要单独看。
- 像素画：`node scripts/clean-image.mjs pixel -o 输出 输入.png…` 在原生网格上处理：合并近似色（OKLab，加重色度差，免得暗绿、暗红被并进黑色），把反差小的孤立杂点并入周围主色（判断孤立算上对角；眼睛、高光、火星这类反差大的单像素保留），透明度只留两档，去掉漂浮的小碎点。整数倍放大的图自动还原并保持尺寸；`--keep-alpha` 保留刻意做的半透明光效和影子。多帧一起传会共用一套颜色。
- 生成器的“假像素”图加 `--grid auto` 或 `--grid <大致格宽>`：按检测到的网格取每格中心的中位色，还原成真像素，再用 `--scale` 整数倍放大。规整的木板、砖块也会被测成网格，所以不自动检测。生成器常把五官、胡茬、细发画得比整体的像素更细，按粗网格取样会把它们抹掉或放成整格黑块，脸就变了；工具会把这类格子按半格取样，身体仍是干净的大像素。项目要求像素大小完全统一时才用 `--uniform`：它会丢掉这些细节，结果不能直接交付，要先用项目的生图管线按这个格宽重画五官。
- `--colors N` 限色只适合图标：人物限色会把肤色并进白衣。不用模糊、双边滤波或通用降噪处理像素画，它们会抹出新的渐变和半透明边。
- 插画：`node scripts/clean-image.mjs cel -o 输出 输入.png…` 以 L0 平滑为底，把细纹和几像素大的斑块里反差低的部分去掉；线条、高光、硬边明暗和渐变保留，软线条收紧，透明度不动。默认档适合赛璐璐和动画风；场景、厚涂、半写实图用 `--strength light`，只去最细的纹理；`--sharpen 0` 不收线。
- 去噪不是抹平：赛璐璐要留硬边明暗分层，不能退成平涂；需要质感就加统一可控的纹理。
- 不用双边或导向滤波（会抹成塑料感），也不用扩散模型低强度重绘（会改眼睛和造型）。神经网络超分去噪（如 Real-ESRGAN 动漫模型）去纹理干净，但会加粗线条、让唇色发色变艳、在半写实场景上画出伪细节，而且属于用另一个图像模型改图，要用户或项目允许。
- 去噪只能并掉低反差的杂点。画得过碎、反差大的花纹清不干净，要简化或重画。
- 视频里的噪点多半来自素材本身，先清素材再重录重渲；生成视频的纹理游动和闪烁靠降噪去不掉，换成实机画面或重做。

## 宣传图、截图与商店素材

- 优先用产品自己的画面组合：真实场景、角色、标志和字体；不另造与产品画风不符的“宣传插画”。
- 截图选真实帧：主体完整，不被横幅或界面遮挡，不在受击闪白这类瞬时状态；一组截图覆盖不同内容；不修图冒充实机。
- 封面和缩略图按实际显示尺寸检查可读性。

## 视频

- 以真实画面和产品自己的音乐音效为主，少用标题卡、法阵、粒子、墨迹转场这类通用包装，也少用到处都在用的授权配乐。
- 画面重录后音效要跟着重混，不沿用旧录像的声音。
- 开头几秒就给真实内容；剪辑点落在音乐的小节或拍点上。
- 同质的多个版本只留最好的一支。
- 检查平台自动截取的封面帧，避开闪白、黑屏和遮挡。

## 生成来源标记与水印

- 分清文件元数据和内嵌水印。文件元数据（C2PA / Content Credentials、XMP、EXIF、IPTC、注释、PNG 文本块及尾部附加字节）可以在交付副本上无损剥离：`node scripts/clean-image.mjs meta 图.png|jpg|webp…` 列出各块/段，加 `--strip 副本` 保留压缩图像数据、色彩配置和 APNG 动画帧（逐字节不变），只删元数据；`cel`、`pixel` 写出的 PNG 本来就只带像素与色彩块。JPEG / WebP 若 EXIF 含非 1 的 `Orientation`（旋转/翻转标记），`--strip` 默认拒绝以免悄悄旋图，需先按方向重存像素或确认后加 `--drop-orientation`。包体里的内联图（如网页里的 base64 图）和打包资源同样要查。
- SynthID 这类像素或信号水印不在本技能处理范围内；转码、截图、缩放、裁切和上面的去噪都不能证明已去除。没有检测器就写明未核验，需要无水印素材时从上游换用无水印来源。
- 原件和来源记录（提示词、参考图、哈希、服务与日期）保留备查；平台或法规要求保留的披露与必需版权信息不擅自删除。

## 验收

- 做新旧对照拼图（`--review` / `review`）：同尺寸、同场景并排看；整组放在一起看是否统一。
- 去噪前后看对比图放大区，确认眼睛、高光、细线、透明边和文字都在；写明 `measure` 的前后数字（颜色数、孤立像素、平坦区细纹；同尺寸时补色调偏移、线条锐度）。
- 改了源图，就按依赖顺序重建所有用到它的成品：先重建被引用的中间素材，再重建图集、图标、商店图、截图和视频，然后按本节查一遍。顺序颠倒时，成品里会留着旧素材。
- 在真实位置看：产品界面里、商店页上、播放器里、缩略图尺寸下。
- 交付物逐个查元数据，构建产物和线上副本也查；写明检查范围和无法核验的部分。
